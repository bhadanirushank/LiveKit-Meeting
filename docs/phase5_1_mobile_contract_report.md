## Session evidence
- **Token formats:** `atk_<secure-random-url-safe-value>`, `rtk_<secure-random-url-safe-value>`.
- **Token entropy:** 256 bits of SecureRandom entropy for both tokens.
- **Digest algorithm:** SHA-256 for persistent hashes.
- **Access-token lifetime:** 30 minutes.
- **Refresh-token lifetime:** 30 days.
- **installationId behavior:** Treated as non-secret metadata. Cannot authenticate session, inherit meeting authorization, or recover old session.
- **Refresh atomicity:** Handled via PostgreSQL row locking.
- **Concurrent refresh results:** Exactly one concurrent refresh succeeds, others fail and old token is invalidated.
- **Replay rejection:** Replaying old refresh tokens fails.

## Token-delivery evidence
- The previously committed fixed 16-byte test value was identified.
- It was removed from backend/build.gradle.kts.
- .gitleaksignore was removed.
- Test tasks now generate a dynamic cryptographically secure 32-byte key.
- The generated bytes are encoded with standard Base64.
- The same generated key is reused across relevant tasks/processes within one controlled Gradle execution where restart replay requires it.
- No dynamic key is printed or persisted.
- Runtime startup requires TOKEN_DELIVERY_ENCRYPTION_KEY_B64.
- Missing configuration fails startup.
- Malformed Base64 fails startup.
- Values decoding to 16, 24, 31 or 33 bytes fail startup.
- Exactly 32 decoded bytes succeeds.
- AES/GCM/NoPadding uses the decoded 32-byte key directly.
- The key is not derived from access token, refresh token, JWT secret or LiveKit API secret.
- PostgreSQL ciphertext and IV remain separate.
- The Android client receives a normal LiveKit token response and never receives database ciphertext or key material.
